# Privacy desktop builds

GitHub Actions owns manually requested builds of the privacy branch. Its matrix matches all six targets in the upstream CI platform specification: macOS, Windows and Linux, each x64 and arm64. Each job uses a native runner, the committed lockfile and existing desktop preparation/build/packaging scripts. No vendor credentials, notifications or reporting services are required.

The dispatch selector defaults to all platforms; macOS, Windows or Linux may be selected independently for retries. Content-addressed Gen UI vendor snapshots must be checked out byte-for-byte on every OS; their hash validation remains enabled.

Order: checkout requested commit → install pinned tools/dependencies → build backend → prepare and build desktop/Agent → package and verify runtime closure → collect installers and SHA-256 manifest → upload Actions artifact. Each architecture owns its isolated workspace and artifact; one failed job does not cancel the other targets. Build jobs have read-only repository permission; uploads use the Actions artifact service.

An optional dispatch `release_tag` requests a public GitHub Release and requires all six platforms. The release job is the only owner of publication and the only job with repository write permission. After all builds succeed, it downloads isolated artifacts, verifies every installer against its platform checksum, rejects missing targets, duplicate filenames or mismatched metadata, and assembles one SHA-256 manifest and source/build manifest. It creates a new draft for that tag, uploads the verified assets, then publishes. An existing release must never be overwritten; failed uploads leave an unpublished draft for inspection. Initial delivery may reuse successful artifacts from earlier runs; the manifest must preserve their actual source commits. Releases expose installers directly without Actions login or artifact retention limits. This does not create or enable an application update feed.

Packages retain the fork's disabled reporting/update behavior. The workflow explicitly disables optional reporting build flags and signing discovery. macOS and Windows packages are unsigned. Open-source upstream Computer Use placeholders remain placeholders; normal custom model and terminal features stay enabled. Build dependencies are downloaded during CI, without bundling private configuration or personal model credentials.

Acceptance: all six jobs produce platform-labelled downloadable installers or executable archives, containing the built Agent and runtime resources, plus source-commit/build metadata and checksums. Failed builds must be repaired and rerun, and cannot be described as delivered. When a release tag is supplied, all installers and combined verification metadata must be publicly downloadable from Releases; checksum tampering and incomplete target sets must prevent publication.
